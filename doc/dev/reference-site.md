# Reference site

Generated Helm chart values and CRD API reference, published to https://weka.github.io/weka-operator/. Sources live in `website/`.

- Preview locally: `website/preview-docs.sh` (serves at http://127.0.0.1:8000). CI-style build: `website/preview-docs.sh --build-only`.
- Helm Chart page: `charts/weka-operator/README.md`, generated by `make helm-docs` from annotations in `charts/weka-operator/values.yaml`.
- CRD pages: crd-ref-docs output over `pkg/weka-k8s-api/api/v1alpha1`, split per resource by `website/scripts/split-crd-docs.py`. The nav grouping is `NAV_GROUPS` in that script, which also rewrites the `nav:` block of `website/mkdocs.yml`.
- Publishing: `.github/workflows/docs.yaml` builds the site with `website/` from the checked-out ref (the default branch for release runs, the dispatched branch for manual runs) and the API types and chart (`pkg/weka-k8s-api`, `charts/weka-operator`) from the latest stable `v1.*` tag, after "Package Operator (HELM)" succeeds on `release/v1`, or on manual dispatch. A manual run can take the content from another ref with `gh workflow run docs.yaml -f content_ref=main`; the next release overwrites it. Pull requests get a `docs-site` artifact; serve it with `python3 -m http.server -d <dir>` (MkDocs directory URLs break over `file://`).
